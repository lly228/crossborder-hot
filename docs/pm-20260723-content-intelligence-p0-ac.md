# 跨境HOT P0内容智能升级验收标准

## 范围

在不引入框架和构建工具、保持双击`index.html`可用的前提下，完成四项改造：

1. 页面展示数据鲜度和抓取状态
2. 精选状态与热度分解耦
3. 事实摘要、推荐理由、卖家影响和行动建议分字段保存
4. 同一事件的多信源条目聚合，并在精选页展示今日重要5件事

## B1 实体与生命周期

### 资讯条目

生命周期：发现 → 抓取成功 → 待加工 → 已加工 → 归档

牵连关系：

- 抓取成功时更新数据鲜度元数据
- LLM加工后更新评分、精选状态和卖家行动字段
- 归档时保留`eventId`，防止同一旧事件被重新收录
- 条目字段缺失时前端兼容旧数据，不阻塞页面渲染

### 事件

生命周期：单信源事件 → 多信源事件 → 超出展示时间窗

牵连关系：

- 多条资讯共享`eventId`时，精选流只展示一个主条目
- 主条目由评分、时间和摘要完整度决定
- 事件保留全部信源链接，原始条目不删除

### 数据鲜度元数据

生命周期：未生成 → 抓取成功或部分失败 → 页面按时间差计算新鲜、延迟或停更

牵连关系：

- 抓取脚本每次结束写入`data/meta.js`
- 页面不依赖网络请求读取状态
- 元数据缺失时页面显示更新时间未知，不隐藏资讯

## B2 五个必问

Q1 空状态：没有资讯时显示暂无资讯；没有元数据时显示更新时间未知；没有可聚合事件时隐藏今日重要5件事

Q2 失败：

- 单个来源发现失败：继续处理其他来源，元数据记录失败来源
- 所有来源失败：保留原有资讯，元数据状态为失败
- LLM不可用：保留抓取摘要和启发式评分，新字段为空
- 数据字段不完整：前端使用默认值，不抛出脚本错误

Q3 被引用：归档、日报、主题和收藏继续引用原资讯ID；聚合只改变展示，不删除底层条目

Q4 并发：GitHub Actions继续使用单工作流写入；事件ID由数据内容确定，多次运行结果稳定

Q5 后悔：所有新增字段向后兼容；移除`meta.js`或新增字段后页面仍可展示旧版资讯

## B3 输入输出链

输入：

- 四个公开资讯源 → 来源不可用时记录失败并继续
- `data/news.js`旧数据 → 缺少新字段时自动补默认值
- LLM返回JSON → 字段逐项校验，非法字段不覆盖旧值

输出：

- `data/news.js` → 前端、日报、归档共同消费
- `data/meta.js` → 顶部鲜度状态消费
- 精选时间线 → 按事件折叠并保留相关信源
- 今日重要5件事 → 只在精选视图展示

## B4 子功能优先级

### 必须在V1实现

1. 新数据契约和旧数据兼容
2. 抓取结果元数据
3. 独立`selected`字段
4. 稳定`eventId`生成与多信源聚合
5. 今日重要5件事
6. LLM字段校验和正向提示词

### 应该在V1实现

1. 页面鲜度提示
2. 推荐理由、卖家影响、行动建议和截止日期展示
3. 事件相关信源链接
4. 新增逻辑测试

### 可以延后

1. 站内详情页
2. 分享URL状态
3. RSS、API和Agent Skill

## B5 验收标准

### AC-1：旧数据兼容

- 前置：条目只有原有字段
- 操作：双击打开`index.html`
- 期望：精选、全部、日报、主题和收藏均可渲染，控制台无错误

### AC-2：鲜度状态

- 前置：`data/meta.js`存在且包含最近成功抓取时间
- 操作：打开页面
- 期望：顶部显示最近更新时间；超过24小时显示延迟，超过72小时显示停更

### AC-3：部分来源失败

- 前置：一个来源发现函数抛出异常
- 操作：运行抓取脚本
- 期望：其他来源继续处理，`sourceResults`记录失败来源，脚本仍写回数据和元数据

### AC-4：精选解耦

- 前置：存在高分但`selected=false`和低分但`selected=true`条目
- 操作：打开精选视图
- 期望：只展示`selected=true`条目，热度分不直接决定是否出现

### AC-5：事件聚合

- 前置：两条不同来源资讯拥有相同`eventId`
- 操作：打开精选视图
- 期望：时间线只展示一个主条目，并显示另有1个信源及两个来源链接

### AC-6：今日重要5件事

- 前置：最新三天存在至少5个精选事件
- 操作：打开精选视图
- 期望：分类筛选上方显示不超过5个事件，按影响分和信源数排序

### AC-7：内容字段

- 前置：条目含`summary`、`why`、`impact`、`action`和`deadline`
- 操作：查看该条目
- 期望：事实摘要、推荐理由、卖家影响、建议动作和截止日期分别展示

### AC-8：LLM降级

- 前置：未配置`CBHOT_LLM_API_KEY`
- 操作：运行抓取脚本并打开页面
- 期望：新条目带启发式评分、精选状态、标签和事件ID，页面正常展示

### AC-9：回归

- 前置：完成改造
- 操作：运行`python scripts/test_fetch.py`和`node --check assets/app.js`
- 期望：全部测试通过，命令退出码为0
